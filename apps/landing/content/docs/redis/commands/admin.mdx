title: Administration
description: Look up RedisAdmin and its server, ACL, config, client and diagnostics commands.
---

`RedisAdmin` groups the commands that manage a server instead of its data. Each call runs on a leased session of an explicitly configured backend, and nothing is broadcast to other nodes.

**Example** (Reading Server Information)

```ts twoslash
import { Effect } from "effect";

import { RedisAdmin } from "@effect-kit/redis";

const program = Effect.gen(function* () {
  const admin = yield* RedisAdmin;

  const info = yield* admin.info(["server"]);
  //    ^?
  const size = yield* admin.dbsize();
  //    ^?

  return { info: info.sections.map((section) => section.name), size };
});
```

`info` parses the reply into sections. Values stay strings, so versions and counters are not turned into JavaScript numbers.

<Callout type="warn" title="Some replies are redacted">
  Replies that can contain secrets or application data, such as `configGet`, `aclList`, `clientList`
  and `slowlogGet`, are wrapped in `Redacted`. Read them with `Redacted.value`.
</Callout>

`RedisAdmin` is provided by the Node and Bun layers and needs `RedisSessions`. Upstash has no `RedisAdmin`. Two members are not commands. `admin.execute(command)` runs any `Command` on a session, and `admin.withSession(body)` gives you the `RedisSession`.

## Connection checks on `Redis`

| Method              | Command | Reply type   | Purpose                         |
| ------------------- | ------- | ------------ | ------------------------------- |
| `redis.ping`        | `PING`  | `void`       | Check that the server answers.  |
| `redis.pingMessage` | `PING`  | `Uint8Array` | Send a message and get it back. |
| `redis.echo`        | `ECHO`  | `Uint8Array` | Send a message and get it back. |
