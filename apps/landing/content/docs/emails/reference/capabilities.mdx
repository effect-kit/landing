title: Capabilities

`EmailCapabilities` describes what a provider layer can send. Read it from `email.capabilities`. How the checks run is described in [Capabilities](/docs/emails/capabilities).

## `EmailCapabilities`

| Field               | Type                               | Description                             |
| ------------------- | ---------------------------------- | --------------------------------------- |
| `text`              | `boolean`                          | Accepts a `text` body.                  |
| `html`              | `boolean`                          | Accepts an `html` body.                 |
| `htmlAndText`       | `boolean`                          | Accepts both bodies in one message.     |
| `senderName`        | `boolean`                          | Accepts a display name on `from`.       |
| `cc`                | `boolean`                          | Accepts `cc`.                           |
| `bcc`               | `boolean`                          | Accepts `bcc`.                          |
| `replyTo`           | `"none" \| "single" \| "multiple"` | Number of reply-to addresses allowed.   |
| `headers`           | `boolean`                          | Accepts custom headers.                 |
| `attachments`       | `boolean`                          | Accepts attachments.                    |
| `inlineAttachments` | `boolean`                          | Accepts attachments with a `contentId`. |
| `idempotency`       | `Idempotency`                      | Whether and how a key is honored.       |

The schema requires `text` or `html` to be true, requires both when `htmlAndText` is true, and requires `attachments` when `inlineAttachments` is true. `Email.make` fails with a `TypeError` otherwise.

## `Idempotency`

| Shape                            | Meaning                                               |
| -------------------------------- | ----------------------------------------------------- |
| `{ mode: "unsupported" }`        | A key fails with `UnsupportedFeatureError`.           |
| `{ mode: "replay", retention? }` | A repeated key returns the earlier outcome.           |
| `{ mode: "reject", retention? }` | A repeated key fails with `IdempotencyConflictError`. |

`retention` is a `Duration`. It is declared, not enforced.

## `RetryAfter`

A schema for a finite, non-negative `Duration`. It is the type of `retryAfter` on `RateLimitedError`, `QuotaExceededError` and `ProviderUnavailableError`, and of `retention`.

`lettermint` also reports its provider name as `lettermint/sandbox` when `sandbox: true`. Some providers reject a field for reasons that are not capability flags, such as the `@` Lettermint needs in an inline `contentId`. Those fail with `InvalidMessageError`.

The `plunk` row means a message with a `text` body fails the capability check, so Plunk takes `html` only, with no `cc`, `bcc`, reply-to, headers or attachments.
