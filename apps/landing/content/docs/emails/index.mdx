`@effect-kit/emails` gives Effect programs one `Email` service. You pick a provider by providing its Layer, and the same `email.send` call works with Resend, Amazon SES, Postmark, SendGrid and 12 others.

The package checks a message against the provider's capabilities before any request is made, and you install only the SDK of the provider you use.

**Example** (Sending a Welcome Email With Resend)

```ts twoslash
import { Config, ConfigProvider, Effect, Layer } from "effect";
import { Email } from "@effect-kit/emails";
import * as Resend from "@effect-kit/emails/resend";

// Reads RESEND_API_KEY from the environment
const EmailLive = Resend.layerConfig().pipe(
  Layer.provide(ConfigProvider.layer(ConfigProvider.fromEnv())),
);

const program = Effect.gen(function* () {
  const email = yield* Email;
  const receipt = yield* email.send({
    from: "hello@example.com",
    to: "ada@example.com",
    subject: "Welcome",
    text: "Your account is ready.",
    html: "<p>Your account is ready.</p>",
  });
  return receipt;
  //     ^?
});

Effect.runPromise(program.pipe(Effect.provide(EmailLive)));
```

`email.send` succeeds with a `SendReceipt` when the provider accepts the message. It fails with an `EmailError` otherwise.

## What it is not

The message model is the whole feature set. The package has:

- No tags, metadata, scheduling or template ids on a message. Unknown keys are rejected.
- No template store. [React templates](/docs/emails/react-templates) render to HTML and text before you send.
- No automatic retries or failover. You decide when to send again.
- No delivery tracking. A receipt means the provider accepted the message, not that it arrived.
