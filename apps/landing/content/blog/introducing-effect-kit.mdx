Effect Kit is a set of open-source packages for [Effect](https://effect.website). Each one brings a piece of infrastructure your app already depends on into Effect, in the shape Effect code expects: a service you `yield*`, a Layer you provide, and typed errors you can match on.

The first two packages are out today: `@effect-kit/redis` and `@effect-kit/emails`, both at 0.1.0.

## How a package fits your app

Every package follows the same four rules:

1. Your program stays an ordinary Effect program.
2. The package adds one service to context, with typed errors.
3. You provide a Layer for it. The Layer owns clients and connections and closes them with the scope.
4. You can swap the runtime, the provider or a test Layer without touching the program.

That last point is the reason the kit exists. Code that talks to Redis or sends email should not care whether it runs on Node.js or Bun, or whether the email goes through Resend or Amazon SES.

## Redis

`@effect-kit/redis` is a native Redis client. It speaks RESP itself, so Effect is its only dependency. Commands are typed, connections are scoped, and it covers pipelines, transactions, Pub/Sub, Streams, Cluster and Sentinel.

```ts twoslash
import { Effect } from "effect";
import { Redis } from "@effect-kit/redis";

const program = Effect.gen(function* () {
  const redis = yield* Redis;

  yield* redis.set("greeting", "hello");
  return yield* redis.get("greeting");
});
```

It runs on Node.js and Bun over native sockets, and on Deno and Cloudflare Workers through Upstash HTTP. When a connection drops, the `ConnectionError` says how far the command got, so you know when a retry is safe.

Read the [Redis docs](/docs/redis) or see [Redis for Effect](/redis).

## Emails

`@effect-kit/emails` is one `Email` service across 16 providers, including Resend, Amazon SES, Postmark, SendGrid, Mailgun and SMTP. You install only the SDK you use.

Each provider declares what it can carry. A message that needs a feature the provider lacks fails before any request is made, instead of halfway through a send. Every `EmailError` also says whether the provider may have accepted the message, so retries stay safe.

Read the [Emails docs](/docs/emails) or see [Email for Effect](/emails).

## What comes next

Storage is next: object storage with put, scoped get, head, delete and paginated listing, in the same shape as the others.

The packages are Apache-2.0 and developed in the open on [GitHub](https://github.com/effect-kit). Issues and pull requests are welcome.
